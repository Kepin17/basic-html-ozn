4 · GitHub & Pull Request

GitHub adalah tempat repositori-mu "hidup" di internet: cadangan, portofolio, dan ruang kolaborasi dengan tim.

Langkah pertama kali

  1. Daftar di github.com, lalu klik New repository. Beri nama, pilih Public/Private. Jangan centang "Add README" bila repositori lokalmu sudah ada.
  2. Hubungkan repositori lokal ke GitHub lalu unggah:
git remote add origin https://github.com/NAMAKAMU/proyek-pertama.git
git branch -M main
git push -u origin main        # -u: ingat pasangan main ↔ origin/main

Autentikasi

CaraKeterangan
HTTPS + Personal Access TokenMudah dimulai. Password akun tidak dipakai lagi; buat token di Settings → Developer settings
SSH key (disarankan)ssh-keygen -t ed25519 -C "kamu@contoh.com" lalu tempel kunci publik (.pub) di Settings → SSH keys
Jangan pernah commit rahasia (password, token, file .env, kunci API). Begitu masuk riwayat Git ia sulit dihapus dan bisa dibaca siapa saja bila repo publik. Pakai .gitignore.
# .gitignore (contoh proyek web)
node_modules/
.env
.DS_Store
dist/
*.log

Praktik: remote, push, dan pull

Simulator memperlakukan https://github.com/kamu/proyek.git sebagai remote. Setelah push pertamamu, tekan 👥 Teman push untuk mensimulasikan rekan tim yang mengunggah komit lebih dulu.

Alur kolaborasi: GitHub Flow & Pull Request

Fork / clone→Branch fitur→Commit & push→Buka Pull Request→Review & diskusi→Merge ke main
IstilahPenjelasan
Clonegit clone <url>: salin repo ke komputermu (otomatis ada remote origin)
ForkSalinan repo orang lain di akunmu, untuk berkontribusi ke proyek yang tidak kamu miliki
Pull RequestMeminta pemilik repo mengambil perubahan dari branch-mu; ada diskusi, review, dan pemeriksaan otomatis (CI)
IssueCatatan bug/ide/tugas. Tulis Closes #12 di PR agar issue tertutup otomatis saat merge
Branch protectionAturan agar main hanya bisa berubah lewat PR yang lolos review

Pull Request yang baik

  • Kecil dan fokus: satu tujuan per PR (idealnya < 400 baris berubah).
  • Judul seperti pesan komit: feat(login): tambah login dengan Google.
  • Deskripsi: apa yang berubah, mengapa, cara mengujinya, tangkapan layar untuk perubahan UI.
  • Tautkan issue (Closes #12). Pastikan pemeriksaan otomatis hijau.
  • Sebagai peninjau: komentar yang sopan dan spesifik; tanyakan alasan, bukan menyalahkan orang.
