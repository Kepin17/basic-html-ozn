6 · Undo & Konflik

Kesalahan itu pasti terjadi. Yang membedakan pemula dan profesional adalah tahu cara membatalkannya dengan aman.

Peta penyelamat

SituasiPerintahAman?
Batalkan edit di berkas (belum add)git restore index.html⚠ perubahan hilang permanen
Salah add, keluarkan dari staginggit restore --staged index.html✅ isi berkas tetap
Batalkan komit terakhir, simpan perubahannyagit reset --soft HEAD~1✅ (lokal saja)
Batalkan komit terakhir dan perubahannyagit reset --hard HEAD~1⚠ perubahan hilang
Batalkan komit yang sudah di-pushgit revert HEAD✅ membuat komit pembatal baru
Perlu pindah branch tapi pekerjaan belum selesaigit stash → git stash pop✅
Salah ketik pesan komit terakhirgit commit --amend✅ (jika belum di-push)
Aturan: komit yang sudah dibagikan (di-push) jangan ditulis ulang dengan reset/amend. Gunakan revert yang tidak mengubah riwayat.

Lab A · Membatalkan kesalahan

Repositori punya 3 komit. Selesaikan misi satu per satu dan amati ketiga area serta grafik.

Konflik merge

Konflik terjadi bila dua branch mengubah baris yang sama di berkas yang sama. Git tidak mau menebak, jadi ia meminta kamu memilih. Berkas diberi penanda:

<<<<<<< HEAD
<h1>Judul Utama</h1>          ← versi branch kamu saat ini (main)
=======
<h1>Judul Fitur</h1>          ← versi branch yang digabung
>>>>>>> fitur-judul
  1. git merge fitur-judul → muncul CONFLICT.
  2. Buka berkas, putuskan isi akhirnya (salah satu, atau gabungan), lalu hapus ketiga penanda.
  3. git add index.html menandai konflik beres.
  4. git commit menyelesaikan merge.
Tips mencegah konflik: tarik perubahan terbaru sering-sering (git pull), buat branch yang pendek umurnya, dan komunikasikan siapa mengerjakan berkas apa.
